
# Claude Code 的 ultracode 到底是什麼?一篇搞懂這個「燒錢但很猛」的模式

最近用 Claude Code 的人,可能在某些教學文章或推文裡看到一個詞:**ultracode**。然後跑去輸入框打 `/ultracode`、`/ultrathink`、`/ultrareview`⋯⋯結果發現通通沒這個指令,一臉問號。

	別急,你沒做錯什麼,只是搞混了「指令」和「設定值」這兩個不同的東西。這篇用最白話的方式幫你講清楚。

## 先講結論:它不是斜線指令

`ultracode` **不是**一個 `/` 開頭的斜線指令。它是 Claude Code 裡一個叫「effort(用力程度)」的設定值。

你可以把 effort 想成 Claude 寫程式時的「認真等級」:

|等級|大概是什麼感覺|
|---|---|
|`high`|日常預設,該認真的時候會認真|
|`xhigh`|想得更深,適合難解的 bug、架構評審|
|`ultracode`|`xhigh` 再加上「自動拆任務、派一堆分身去做」|

所以正確的開啟方式長這樣:

```
/effort ultracode
```

是 `/effort` 這個指令,後面接 `ultracode` 這個參數。不是 `/ultracode`。這就是為什麼你直接打 `/ultracode` 會找不到。

## ultracode 真正特別的地方:它會「自己派工」

一般你跟 Claude Code 對話,是一來一回:你問一句、它做一件事。

開了 ultracode 之後,Claude 會自己判斷:「這個任務有點大,我應該把它變成一個 workflow(工作流),派出一群分身(subagents)同時去做,做完還互相檢查彼此的成果。」

這就是 Anthropic 最近推出的 **dynamic workflows(動態工作流)**機制。打個比方:

> 平常的 Claude Code 像是請一個很厲害的工程師幫你做事。 開了 ultracode,比較像是這位工程師當起小組長,臨時召集一整隊人分頭做,最後彙整一份報告給你——而且隊員之間還會互相 review,挑出彼此的錯。

官方文件講得很直接:開了 ultracode 之後,一個請求可能會變成連續好幾個 workflow——一個負責理解程式碼、一個負責改、一個負責驗證。

## 那「ultracode」這個字也能直接打在句子裡?

可以,而且這是更省的用法。

- **整個 session 都開**:`/effort ultracode`。從此這次對話的每個任務都會走這套高消耗流程,直到你關掉或開新對話。
- **只想針對某一個任務開**:直接把 `ultracode` 這個字寫進你的提示裡。例如:

```
ultracode: 幫我檢查 src/routes/ 底下每個 API 端點有沒有漏掉權限驗證
```

這樣只有這一個任務會用 workflow 跑,不會影響整個 session 的設定。Claude Code 會把這個關鍵字在輸入框裡反白標起來,讓你知道它接住了。

> 小提醒:在比較舊的版本(v2.1.160 之前),這個觸發關鍵字其實是 `workflow` 不是 `ultracode`。所以如果你看到舊文章叫你打 `workflow`,那是舊版的寫法。不確定的話,直接用中文講「幫我跑一個 workflow」也通。

## 重點來了:這東西很燒額度 ⚠️

這是整篇最需要你記住的一段。

ultracode 會一次派出一大群分身(官方說單次最多可以到 1,000 個 agents),每個都在燒 token。所以它的消耗,跟平常一來一回的對話完全不是同一個量級。

社群裡第一週的災情長這樣:

- 有人用 $200/月 的 Max 方案,光開 dynamic workflows 玩一天,就燒掉整週額度的 20%。
- 有 $20 Pro 方案的使用者,大概十分鐘就觸頂。

Anthropic 自己也沒在藏,官方說明白寫了這會「消耗遠比一般 session 多的 token」,並建議你先從一個小範圍的任務開始試。

所以實務上的省錢心法:

1. **不要長期把 ultracode 當預設**。做完大任務,記得用 `/effort high` 降回來。
2. **先在小範圍試水溫**。要審查整個專案?先只跑一個資料夾,看看大概燒多少。
3. **盯著用量**。輸入 `/workflows` 可以看到每個分身即時的 token 消耗,覺得不對隨時可以喊停,已經做完的部分不會白費。

## 什麼時候值得用?什麼時候別用?

**值得用** 👍

- 整個專案的安全性 / 權限漏洞掃描
- 大型的框架或 API 遷移(幾百個檔案那種)
- 需要從多個角度交叉驗證的複雜根因分析
- 高風險的方案評審(讓不同分身先各自寫方案,再互相反駁)

**別用,殺雞用牛刀** 👎

- 改個錯字、調個 import、修個小樣式
- 範圍很明確的小功能
- 你已經反覆在用的固定提示詞(那個做成 slash command 或 skill 更好)
- 預算很緊、只是想隨便探索一下

## 怎麼開?選單裡沒看到怎麼辦?

輸入 `/effort ultracode` 就行。如果選單裡根本沒有這個選項,按順序檢查:

1. **版本太舊**——需要 Claude Code v2.1.154 以上,先 `claude --version` 看看。
2. **模型不支援**——ultracode 只在支援 `xhigh` 的模型上出現,其他模型的 `/effort` 選單根本不會有這個選項。
3. **方案設定**——所有付費方案都能用,但 Pro 方案要先去 `/config` 裡把 Dynamic workflows 那一列手動打開。

## 一句話總結

`ultracode` = 用 `/effort ultracode` 開啟的高用力模式,讓 Claude 自動把大任務拆成一群分身平行作業、互相檢查。**威力很強,但很燒額度**——拿來對付大型審查、大遷移很香,日常瑣事千萬別開著。

下次看到別人喊 ultracode,你就知道:那不是斜線指令,是 `/effort` 的參數,而且用之前先看一眼自己的額度 😏
